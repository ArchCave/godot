## 1. 이동/점프 물리 분석 (Game Feel)

**평가: C+ (개선 필요)**

### 현재 수치 분석

| 파라미터 | 현재 값 | 일반적인 2D 플랫포머 범위 |
|----------|---------|--------------------------|
| `move_speed` | 25 px/s | 150~300 px/s |
| `gravity` | 420 px/s^2 | 800~1500 px/s^2 |
| `jump_force` | 100 px/s | 300~500 px/s |

### 문제점

1. **이동 속도가 극단적으로 느림:** `move_speed = 25`는 일반적인 2D 플랫포머의 1/6~1/10 수준이다. 플레이어가 화면을 가로지르는 데 매우 오래 걸려 답답한 조작감을 유발한다.

2. **가속/감속 없음:** `velocity.x = move_input * move_speed`로 즉시 최대 속도에 도달하고 즉시 정지한다. 관성이 전혀 없어 캐릭터가 로봇처럼 움직인다.
   ```gdscript
   # 현재: 즉시 반응 (딱딱한 느낌)
   velocity.x = move_input * move_speed

   # 개선안: lerp를 이용한 부드러운 가감속
   var target_speed = move_input * move_speed
   velocity.x = move_toward(velocity.x, target_speed, acceleration * delta)
   ```

3. **중력과 점프력의 비율 불균형:** 점프 체공 시간 = `2 * jump_force / gravity` = 약 0.48초. 짧은 체공 시간 자체는 나쁘지 않으나, 느린 이동 속도와 결합하면 점프로 이동할 수 있는 수평 거리가 약 12px에 불과하여 플랫포밍이 사실상 불가능하다.

4. **가변 점프 높이 미구현:** 점프 버튼을 짧게 누르든 길게 누르든 동일한 높이로 점프한다. 숏 점프/풀 점프 구분이 없어 조작의 섬세함이 떨어진다.
   ```gdscript
   # 개선안: 버튼을 떼면 점프력 감쇄
   if Input.is_action_just_released("ui_jump") and velocity.y < 0:
       velocity.y *= 0.5
   ```

5. **코요테 타임(Coyote Time) 미구현:** 플랫폼 가장자리에서 떨어진 직후 점프를 입력하면 무시된다. 플레이어가 불공정하다고 느끼는 대표적 요소이다.

6. **점프 버퍼링 미구현:** 착지 직전에 누른 점프 입력이 무시된다. 빠른 연속 점프가 어렵다.

## 2. 점프력 스케일링 밸런스 평가

**평가: D (심각한 밸런스 문제)**

### 현재 스케일링 테이블

| 점수 구간 | 배율 | 실제 점프력 | 예상 점프 높이 |
|-----------|------|------------|---------------|
| 0~59 | 1.0x | 100 | ~11.9 px |
| 60~119 | 1.5x | 150 | ~26.8 px |
| 120~179 | 2.0x | 200 | ~47.6 px |
| 180~239 | 3.0x | 300 | ~107.1 px |
| 240+ | 4.0x | 400 | ~190.5 px |

> 점프 최대 높이 공식: `h = jump_force^2 / (2 * gravity)`

### 문제점

1. **비선형 난이도 곡선:** 60점 구간마다 점프력이 급격히 증가한다. 특히 120->180 구간에서 2.0x->3.0x로의 점프는 레벨 디자인 관점에서 동일 스테이지 내에서 도달 가능한 영역이 갑자기 3배 가까이 늘어나 맵 설계를 극도로 어렵게 만든다.

2. **하드코딩된 임계값:** 점수 기반 성장이 매직 넘버(60, 120, 180, 240)로 하드코딩되어 있다. 밸런스 조정 시 코드를 직접 수정해야 한다.
   ```gdscript
   # 개선안: 데이터 기반 설계
   @export var jump_scale_table: Array[Dictionary] = [
       {"score": 60, "multiplier": 1.5},
       {"score": 120, "multiplier": 2.0},
       # ...
   ]
   ```

3. **최대 배율에 상한 없음:** 240점 이후로는 4.0x에 고정되지만, 4배의 점프력은 대부분의 레벨 구조를 무시하고 뛰어넘을 수 있는 수준이다. 게임의 플랫포밍 요소를 무력화시킬 위험이 크다.

4. **점프력만 스케일링:** 중력은 고정인데 점프력만 증가하므로, 고배율 구간에서 체공 시간이 비정상적으로 길어진다 (1.0x: 0.48초 -> 4.0x: 1.90초). 캐릭터가 달에서 뛰는 것처럼 느껴질 수 있다.

5. **점프력 감소 메커니즘 부재:** 점수는 증가만 하므로 점프력이 절대 낮아지지 않는다. 실수나 리스크 없이 일방적으로 강해지기만 하면 긴장감이 사라진다.

## 3. 데미지/체력 시스템 분석

**평가: C (기본 기능만 존재)**

### 현재 구현

- 초기 체력: 5
- 적 접촉 시 1 데미지
- 체력 0 이하로 게임 오버

### 문제점

1. **무적 시간(i-frame) 미구현:** 적과 겹친 상태에서 매 프레임 `_on_body_entered`가 호출될 수 있어, 한 번의 접촉으로 체력이 순식간에 0이 될 수 있다. 이는 치명적 버그이다.
   ```gdscript
   # 개선안: 무적 시간 추가
   var is_invincible := false

   func take_damage(amount: int):
       if is_invincible:
           return
       health -= amount
       is_invincible = true
       # 시각적 피드백 (깜빡임)
       var tween = create_tween()
       for i in 5:
           tween.tween_property(sprite, "modulate:a", 0.3, 0.1)
           tween.tween_property(sprite, "modulate:a", 1.0, 0.1)
       await get_tree().create_timer(1.0).timeout
       is_invincible = false
   ```

2. **넉백(Knockback) 없음:** 피격 시 캐릭터가 전혀 밀려나지 않아 피격 감각이 없다. 플레이어가 데미지를 받았다는 것을 인지하기 어렵다.

3. **시각/청각 피드백 없음:** 데미지를 받았을 때 화면 흔들림, 히트스톱, 깜빡임, 사운드 등 어떠한 피드백도 없다.

4. **게임 오버 경로가 잘못됨:** `game_over_scene`의 기본값이 `"res://Scenes/level_1.tscn"`으로, 게임 오버 시 게임 오버 화면이 아닌 레벨 1로 돌아간다. 의도된 동작이라면 리스폰이지만, 점수가 `PlayerStats`에 남아있어 점프력이 유지되는 문제가 발생한다.

5. **체력 회복 수단 없음:** 체력은 감소만 하고 회복할 방법이 전혀 없다. 5의 체력으로 전체 스테이지를 클리어해야 하는 것은 (무적 시간이 없는 현재 상태에서) 지나치게 가혹하다.

## 4. 스킬(똥 코인) 메카닉 분석

**평가: B- (독특하지만 불완전)**

### 메카닉 흐름

```
스킬 사용 -> 똥 스폰(지면에) -> 20초 대기 -> 코인으로 변환 -> 플레이어 수집 -> 점수 +1 -> 점프력 업데이트
```

### 긍정적 요소

- **독창적 메카닉:** 자원을 직접 생산하고 시간 후 수확하는 파밍 시스템은 독특하고 재미있는 콘셉트이다.
- **RayCast를 이용한 지면 배치:** 공중에서 스킬을 써도 지면에 정확히 배치되는 점이 잘 구현되어 있다.
- **관심사 분리:** poop_coin.gd가 자체 타이머와 상태 전환을 관리하여 player.gd의 책임을 줄였다.

### 문제점

1. **쿨다운 없음:** 스킬 사용에 제한이 없어 무한 스팸이 가능하다. 20초 대기 × 무한 배치 = 한 곳에 수십 개를 쌓아놓고 한꺼번에 수확하는 것이 최적 전략이 된다.
   ```gdscript
   # 개선안: 쿨다운 시스템
   @export var skill_cooldown: float = 3.0
   var can_use_skill := true

   func _spawn_poop():
       if not can_use_skill:
           return
       can_use_skill = false
       # ... 스폰 로직 ...
       await get_tree().create_timer(skill_cooldown).timeout
       can_use_skill = true
   ```

2. **20초 대기 시간이 과도함:** 빠른 템포의 플랫포머에서 20초는 매우 긴 시간이다. 플레이어가 코인을 배치하고 변환을 기다리는 동안 해당 구역을 떠나야 하는 상황이 발생하며, 되돌아오기 어려울 수 있다.

3. **동시 존재 제한 없음:** 동시에 존재할 수 있는 똥/코인 개수에 제한이 없어 성능 문제가 발생할 수 있다. `queue_free()`로 수집 시 삭제되긴 하지만, 수집하지 않은 코인은 무한히 쌓인다.

4. **공중 스킬 사용 시 RayCast 미충돌 문제:** `ray.is_colliding()`이 false일 때 플레이어 위치에 똥을 배치하는데, 이는 공중에 떠 있는 똥이 되어 부자연스럽다. 공중에서는 스킬 사용을 차단하거나, 낙하 후 지면에 정착하는 로직이 필요하다.

5. **스킬 사용 시 시각적 피드백 부족:** 스킬을 사용했다는 것을 `print("Skill")`로만 확인할 수 있다. 캐릭터 애니메이션, 이펙트, 사운드가 필요하다.

## 5. 적 AI 및 상호작용 분석

**평가: D+ (최소 구현)**

### 현재 구현

- Area2D 기반 정적 적
- 애니메이션만 재생 ("drone")
- 충돌 시 플레이어에게 1 데미지

### 문제점

1. **완전히 정적인 적:** `_process`가 빈 상태로 적이 전혀 움직이지 않는다. 드론이라는 이름과 달리 고정 장애물에 불과하다.

2. **일방적 상호작용:** 플레이어는 적에게 데미지를 받기만 하고 적을 처치할 수단이 없다. `ui_attack` 액션이 `print("Attack")`만 출력하며 실제 공격 로직이 없다.

3. **적 처치 보상 없음:** 적을 처치할 수 없으므로 적과의 상호작용에서 보상이 없다. 적은 순수한 장애물이다.

4. **적 유형의 다양성 부재:** 드론 하나만 존재한다. 다양한 패턴(순찰, 추적, 원거리 공격 등)의 적이 필요하다.

5. **충돌 감지 방식의 위험:** Area2D의 `body_entered`는 겹침 시작 시 한 번만 호출되므로 연속 데미지 자체는 발생하지 않지만, 플레이어가 적을 통과하여 빠져나갈 수 있어 위협감이 감소한다.

### 개선 제안

```gdscript
# 기본 순찰 AI 예시
@export var patrol_speed: float = 50.0
@export var patrol_distance: float = 100.0
var start_position: Vector2
var direction: float = 1.0

func _ready():
    start_position = position
    anim.play("drone")

func _process(delta):
    position.x += patrol_speed * direction * delta
    if abs(position.x - start_position.x) > patrol_distance:
        direction *= -1
        sprite.flip_h = direction < 0
```

## 6. 스테이지 클리어 흐름 분석

**평가: C+ (기능적이나 연출 부족)**

### 현재 흐름

```
플레이어가 깃발 터치 -> 플레이어 물리 비활성화 -> "end" 애니메이션 재생 -> 다음 씬 로드
```

### 긍정적 요소

- `set_physics_process(false)`로 클리어 중 플레이어 조작을 차단하는 점이 적절하다.
- `PackedScene`을 `@export`로 받아 재사용 가능한 구조이다.

### 문제점

1. **점수 초기화 누락:** 스테이지 클리어 시 `PlayerStats.score`가 초기화되지 않는다. 다음 스테이지에서 이전 점프력이 그대로 유지되어 난이도가 무너진다. 의도된 설계인지 명확하지 않다.

2. **연출의 부재:**
   - 클리어 사운드 없음
   - 화면 전환 효과(페이드 인/아웃) 없음
   - 점수 표시/결산 화면 없음
   - 클리어 텍스트나 축하 연출 없음

3. **미수집 코인 처리 없음:** 스테이지에 남은 코인(변환 대기 중인 똥 포함)이 씬 전환 시 그냥 사라진다. 자동 수집하거나 최소한 손실을 알려주는 피드백이 필요하다.

4. **입력 차단의 범위:** `set_physics_process(false)`는 물리만 멈추므로 `_input` 또는 `_unhandled_input`을 통한 입력은 여전히 처리될 수 있다. 완전한 입력 차단이 필요하다.

5. **애니메이션 실패 안전장치 없음:** `animation_finished` 시그널이 발동하지 않으면 게임이 영원히 멈춘다. 타임아웃 백업이 필요하다.
   ```gdscript
   func _on_body_entered(body: Node2D) -> void:
       if not body.is_in_group("Player"):
           return
       body.set_physics_process(false)
       anim_sprite.play("end")
       # 안전장치: 최대 5초 후 강제 전환
       get_tree().create_timer(5.0).timeout.connect(
           func(): get_tree().change_scene_to_packed(scene_to_load)
       )
   ```

## 7. 게임 밸런스 개선 제안

### 우선순위 1 (즉시 수정)

| 항목 | 현재 | 권장 | 이유 |
|------|------|------|------|
| 무적 시간 | 없음 | 1.0~1.5초 | 연속 피격 방지, 공정성 확보 |
| 이동 속도 | 25 | 150~200 | 기본적인 조작감 확보 |
| 점프력 | 100 | 280~350 | 이동 속도 대비 적절한 점프 거리 |
| 중력 | 420 | 900~1200 | 묵직하고 반응 좋은 점프감 |

### 우선순위 2 (핵심 게임플레이)

1. **공격 시스템 구현:** `ui_attack` 액션에 실제 공격 로직을 연결한다. 적 처치 -> 점수 획득의 루프를 추가하여 전투와 파밍 두 가지 성장 경로를 제공한다.

2. **스킬 쿨다운 + 변환 시간 조정:** 쿨다운 3~5초, 변환 시간 8~12초로 조정하여 리듬감 있는 파밍 루프를 만든다.

3. **점프력 스케일링 완화:**
   ```
   현재: 1.0x -> 1.5x -> 2.0x -> 3.0x -> 4.0x
   권장: 1.0x -> 1.15x -> 1.3x -> 1.45x -> 1.6x
   ```
   점프력 증가는 보조 수단이어야 하며, 레벨 디자인을 파괴하면 안 된다.

4. **게임 오버 처리 개선:** 게임 오버 전용 씬을 만들어 점수 표시, 재시작/메인 메뉴 선택지를 제공한다. `PlayerStats.score`를 적절히 초기화한다.

### 우선순위 3 (게임 필 향상)

1. **가속/감속 커브:** `move_toward()` 또는 `lerp()`로 자연스러운 가감속을 구현한다.
2. **가변 점프 높이:** 버튼 릴리스 시 상승 속도 감쇄.
3. **코요테 타임:** 0.1~0.15초의 가장자리 점프 허용.
4. **점프 버퍼링:** 착지 0.1초 전 입력을 기억.
5. **스쿼시 & 스트레치:** 점프/착지 시 스프라이트 스케일 애니메이션.
6. **화면 흔들림:** 피격, 착지 시 카메라 셰이크.
7. **히트스톱:** 피격 순간 0.05~0.1초 게임 일시 정지.
8. **파티클:** 착지 먼지, 이동 먼지, 피격 이펙트.
